Unitree G1 ROS 2 MuJoCo Workspace Breakdown
Generated: 2026-06-24

Purpose
-------
This repository builds a simulation-first Unitree G1 ROS 2 workspace around MuJoCo. It combines robot description assets, Unitree DDS/MuJoCo bridging, learned locomotion policy execution, simulated sensors, SLAM/Nav2 bringup, dynamic-person tracking, human-aware collision avoidance, and benchmark tooling for person-avoidance experiments.

The stack is intended for simulation and development. It should not be treated as a hardware-ready safety stack without separate validation.


Top-Level Layout
----------------
README.md
  Main user guide with Docker setup, build commands, simulation launch commands, locomotion troubleshooting, and navigation/person-avoidance workflow notes.

docker-compose.yml
  Docker Compose definition for the development/simulation container.

docker/Dockerfile
  Container image definition for ROS 2 Humble, Unitree dependencies, MuJoCo/MJLab tooling, Python dependencies, and simulation build tooling.

ros2_ws/
  ROS 2 workspace. Contains local packages plus vendored Unitree packages and MuJoCo assets.

scripts/
  Host/container helper scripts for building, launching, training policies, replaying policies, benchmarking, and tuning.

vendor/mjlab/
  MJLab reinforcement-learning/training code and exported policy source tree used by the locomotion workflow. This is a vendor/submodule-style dependency rather than a local ROS package.

2. unitree_g1_mujoco_bridge
  Path: ros2_ws/src/unitree_g1_mujoco_bridge
  Build type: ament_python
  Purpose: Runtime ROS 2 nodes that connect MuJoCo/Unitree DDS state to ROS topics, publish simulated sensors, execute learned locomotion policies, generate navigation commands, detect/track people, and apply human-aware safety filters.

  Console executables:
  - g1_mujoco_bridge

  - lidar_person_detector
  - scan_dynamic_filter
  - dynamic_obstacle_tracker
  - human_aware_motion_planner
  - human_collision_avoidance

  Node/module breakdown:
  - g1_mujoco_bridge.py
    Bridges Unitree HG low-state data and low-level motor commands between MuJoCo/Unitree DDS and ROS. Publishes robot state/odometry-style outputs, accepts body position commands, applies motor gains, supports waist locking/balancing, and includes fall damping/startup grace behavior.

  - g1_policy_cmd_vel_controller.py
    Loads a TorchScript/ONNX locomotion policy and converts velocity commands into G1 body joint position commands. Handles policy observation/action dimensions, command velocity limits, startup blend/hold, upright gating, action ramping, policy stand pose behavior, pre-lowstate stand commands, and cmd_vel timeout safety.

  - g1_hold_pose_controller.py
    Publishes fixed/hold pose commands for basic robot pose holding.

  - g1_cmd_vel_teleop.py
    Simple keyboard/manual cmd_vel teleoperation helper.

  - g1_clamp_button.py
    GUI/service helper for clamping/holding robot pose during sensor or visualization testing.

  - g1_sim_sensors.py
    Publishes simulated RealSense/Livox-style sensor topics from MuJoCo or a Python scene approximation. Supports Livox point clouds, world clouds, camera topics, sensor TF, raycast lidar settings, dead-zone/self filtering, fallen-state suppression, and command-velocity fallback for synthetic motion.

  - livox_to_scan.py
    Projects Livox/point-cloud data into a 2D LaserScan for SLAM/Nav2.

  - scan_dynamic_filter.py
    Filters dynamic/tracked obstacle ranges out of LaserScan data before mapping/navigation.

  - pointcloud.py
    Shared point cloud packing/parsing helpers used by sensor and filtering tests.

  - dynamic_obstacle_tracker.py
    Clusters Livox/world point clouds, tracks dynamic obstacles/people, scores person-like clusters, predicts future positions, publishes marker/debug topics and tracked/predicted point clouds, and optionally publishes safety-grid information.

  - lidar_person_detector.py
    Optional LiDAR BEV person detector wrapper with ONNX-model path support and fallback geometric clustering. Publishes person detections used by tracking.

  - human_aware_motion_planner.py
    Samples/scorers local velocity commands using tracked/predicted people, static obstacles, personal-space costs, time-to-collision costs, front-arc social constraints, smoothness/jerk costs, yielding/deadlock behavior, and optional risk-grid visualization.

  - human_collision_avoidance.py
    Hard safety filter for cmd_vel. Consumes predicted/tracked dynamic obstacles and scan data, limits/reverses/laterally biases commands near people, applies emergency stop and corridor checks, and publishes a safe cmd_vel for the locomotion policy.

  - g1_random_explorer.py
    Publishes simple random obstacle-aware velocity commands for exploration tests.

  - g1_waypoint_patrol.py
    Publishes velocity commands to move through a fixed list of waypoints without Nav2 goals.

  - g1_waypoint_explorer.py
    Sends randomized NavigateToPose goals to Nav2 for autonomous exploration.

  - g1_point_goal.py
    Sends explicit NavigateToPose goals from launch parameters or /g1/point_goal. Can validate the requested goal against the global costmap before sending it.

  - g1_frontier_explorer.py
    Frontier-style exploration helper that selects map-frontier goals from occupancy data.

  - g1_slam_reset_monitor.py
    Monitors fall/upright state and resets SLAM/Nav2 mapping after fall transitions as configured.

  - g1_locomotion_diagnostics.py
    Publishes /g1/locomotion_diagnostics to localize command-path and motion failures. Reports states such as waiting for raw commands, missing safe commands, missing policy body commands, safety filter stopping, command sent but no odom motion, and moving/ready.

  - g1_constants.py
    Shared G1 joint names, indices, default positions, and related constants used by controllers/bridge code.

  Tests:

  - test/test_scan_dynamic_filter.py

Main Runtime Graph
------------------
The default full simulation path is:
1. Host script starts Docker/container launch.
2. g1_sim.launch.py starts MuJoCo using run_mujoco_g1.sh.
3. MuJoCo publishes/receives Unitree DDS low-state and low-command data.
4. g1_mujoco_bridge converts Unitree/MuJoCo state and motor commands into ROS-facing topics.
5. g1_policy_cmd_vel_controller consumes safe cmd_vel and lowstate, runs the learned policy, and publishes /g1/body_position_commands.
6. g1_mujoco_bridge sends those body commands back to MuJoCo/Unitree DDS motor command channels.
7. g1_sim_sensors publishes simulated camera/Livox sensor topics.
8. livox_to_scan converts Livox clouds into /scan_raw.
9. scan_dynamic_filter removes tracked dynamic obstacles from scans and publishes /scan.
10. slam_toolbox builds/publishes /map from /scan.
11. Nav2 plans/control navigation using /map, /scan, odometry, and TF.
12. dynamic_obstacle_tracker tracks/predicts people from point clouds and detections.
13. human_aware_motion_planner modifies raw Nav2/explorer cmd_vel for social navigation.
14. human_collision_avoidance applies hard safety filtering to produce /cmd_vel_safe.
15. g1_locomotion_diagnostics reports whether commands and robot motion are flowing correctly.
16. RViz visualizes robot, TF, map, sensors, trajectories, people, and diagnostics markers.

Current Locomotion Startup Safety Defaults
------------------------------------------
The current launch defaults are conservative for debugging immediate falls:
  pre_lowstate_stand_enable: true
  startup_blend_time: 3.0
  startup_hold_time: 2.0
  startup_require_upright: true
  startup_max_recovery_time: 0.0
  policy_action_ramp_time: 2.0
  mujoco_startup_hold_enable: true
  mujoco_startup_hold_timeout: 0.0
  mujoco_reset_on_controller_start: false
  lock_waist: true
  balance_waist: false

These are designed to publish a stable trained stand pose before releasing into policy inference, avoid invalidating the first stand command with a MuJoCo reset, and ramp policy actions in gradually.

Known Build/Runtime Notes
-------------------------
Docker/container install state can become stale if new Python console scripts are added but /workspace/ros2_ws/install is not rebuilt. Rebuild with /workspace/scripts/build_ws.sh inside the container.

The host workspace may contain Docker-generated build metadata that points at /workspace paths. If host-side colcon builds fail with build-time path errors, build inside the container or clean/recreate build/install/log directories intentionally.

The launch wrapper has compatibility guards for optional executables that may be missing in stale installs, but the correct fix is still to rebuild the container workspace.

Some tests should be run package-by-package to avoid Python test package import collisions from multiple package-level test/__init__.py files.

Reference Summary
-----------------
In short, this repository builds:
  1. A Unitree G1 ROS description package.
  2. A MuJoCo/DDS-to-ROS bridge.
  3. A learned policy cmd_vel locomotion controller.
  4. Simulated Livox/camera sensor publishing.
  5. Livox-to-LaserScan conversion and scan filtering.
  6. SLAM and Nav2 launch integration.
  7. Dynamic obstacle/person detection, tracking, prediction, and visualization.
  8. Human-aware local motion planning and hard collision-avoidance cmd_vel filtering.
  9. Explicit point goals, waypoint/random/frontier exploration helpers.
  10. Locomotion diagnostics and SLAM reset monitoring.
  11. Deterministic person-avoidance benchmark tooling.
  12. Dockerized setup/build/launch/training/benchmark helper scripts.
